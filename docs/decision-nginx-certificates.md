# Decision: TLS certificates of the reverse proxy

[← Back to docs](README.md)

**Status:** accepted for `self-signed` (implemented first); `provided` and `letsencrypt` are designed but deferred

## Context

The [nginx](../search/nginx.md) reverse proxy provides HTTPS and the API key in front of the inference engines. It needs a certificate, and the machines are VMs provisioned unattended (cloud-init), where nobody can answer a prompt and where the network is sometimes restricted (see the mirror URL in [decision: VM script generator](decision-vm-generator.md)). Whether the VM has a public domain name, or even Internet access, is not known to the project.

The recorded state already foresees three values for `listen.tls` (see [state format](spec-state-format.md)): `letsencrypt`, `self-signed`, `provided`.

## Options

| Option | Needs | Pros | Cons |
| --- | --- | --- | --- |
| `self-signed` | nothing | Works everywhere, offline, zero-conf | Clients must trust it or disable verification (`curl -k`, SDKs); browsers warn, which hurts the chat interface |
| `provided` | a certificate and a key from the administrator | Fits an internal CA or a wildcard certificate; no network | The files must reach the VM, the key being a secret (see [secrets](spec-script-contract.md#secrets)) |
| `letsencrypt` | a public domain pointing to the VM, port 80 reachable from the Internet (or a DNS challenge) | Trusted by every client; automatic renewal | Fails on private networks; needs an ACME client (`certbot`) and a renewal timer; rate limits when a fleet of VMs is rebuilt |

## Decision

Proposed:

1. **Default: `self-signed`.** It is the only option that needs nothing, so the zero-conf `install --defaults` always converges. The certificate is generated by the script with `openssl`, valid for the `server-name` (default: the hostname) and recorded in the state. It is regenerated only when the name changes.
2. **`provided`** with `--tls-cert <path>` and `--tls-key-file <path>`: the key follows the secret rules (mode `0600` or stricter, never on the command line, never printed).
3. **`letsencrypt`** with `--tls letsencrypt` and a mandatory `--server-name`: allowed only when a public domain is given. It is added after the first two, and a failure to obtain the certificate is exit 5, not a silent fallback to self-signed.
4. The option is `--tls self-signed|provided|letsencrypt`, a single parameter, so switching is a re-run of `install` (idempotence rules of the [contract](spec-script-contract.md#idempotence)). The proxy's `describe` lists it for `apply` and the generator.
5. **No silent downgrade**: the strategy asked for is the one recorded; an unreachable ACME server never produces a self-signed certificate behind the administrator's back.

## Scope of the first implementation

- Only **`self-signed`** is implemented, and it is what `--defaults` gives. It is the default of the `--tls` option, so `install --defaults` and the VM post-install layer need no certificate parameter.
- `--tls` is already part of the proxy's interface (`describe`, `apply`, the generator), and the three values are reserved in the state (`listen.tls`). `provided` and `letsencrypt` are **refused for now with exit 2** and a message saying they are not implemented yet, rather than ignored or replaced by a self-signed certificate (no silent downgrade).
- Adding one later changes only the proxy script (a new certificate step and its options): the CLI, the configuration file format and the state schema stay as they are.

## Consequences

- The chat interface and the clients are given the proxy's URL by `add-upstream`; with `self-signed` they must trust the certificate. The script exposes it (path recorded in the state) so that a client can be configured, and the documentation says that a browser warns until it is trusted.
- Integration order: self-signed with the proxy, then `provided`, then Let's Encrypt (see [scope](#scope-of-the-first-implementation)).
- Health check of nginx (401 without key, success with key) uses the certificate as is: the probe runs locally with the certificate pinned, never with verification disabled.

## Open questions

- ACME challenge type: HTTP-01 only (port 80), or also DNS-01 for private networks with a public name.
- Validity and renewal of the self-signed certificate (suggested: 10 years, no renewal, since it is not a trust anchor).
- Whether the certificate is shared with the chat interface when it is served by the same proxy.
